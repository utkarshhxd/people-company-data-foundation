The system works. Now we make it safe to rely on.

We can drop a messy vendor file into a folder and get back clean, trusted company and people data — with a full trail of where every value came from. That part is finished. What's left is proving it holds up with real-size files and handing it over properly.

What's done Finished

Ten pieces of work, all merged and tested. Each one runs automatically — no one has to press anything between them.

  • ✓Read files as-isCSV and Excel, stored exactly as the vendor wrote them. Nothing gets "helpfully" reformatted on the way in.
  • ✓Work out what each column meanse_mail, mobile_no, org_name — the system maps them itself, and asks a human when it isn't sure instead of guessing.
  • ✓Clean values so they can be comparedWASHINGTON and Washington become the same thing. The original is always kept alongside.
  • ✓Check whether values are usableAn email with no @ is flagged. A phone with no country code is only a warning, not an error.
  • ✓Hold back bad records instead of deleting themNothing is ever thrown away. Bad rows wait in a review queue and a person decides.
  • ✓Recognise the same company across different filesTwo vendors spelled it "Asia Foundation" and "The Asia Foundation" — matched anyway, on the website. Every attribute from both is kept.
  • ✓Pick the one value we trustNewest address wins. Most-agreed-on name wins. Whatever loses is still recorded, with who said it.
  • ✓Trace any value back to its sourceOne command shows the exact file, row and cell a value came from, and why it beat the alternatives.
  • ✓An API to read the dataSearch, view a company, see its full history.
  • ✓DashboardsShows review backlogs and data quality — including how long the oldest item has been waiting.

In progress Nothing right now

All work is committed and pushed. Nothing is half-finished, which is a good place to plan from — there's no partial work to unwind.

What's next 9 phases

None of this is new features. It's the work that turns something that works on my machine into something the team can depend on.

  • 1Test with real-size files The biggest unknown by far. So far the largest file we've run is 19 rows. Real files are far bigger, and we don't yet know how the system behaves at that size.
  • 2Automatic testing on every changeRight now the 205 tests are run by hand. They should run themselves on every push.
  • 3Lock down the APIIt currently has no login. Fine on a laptop, not fine anywhere else.
  • 4AlertsThe dashboards show problems, but nobody gets told. Needs to actually notify someone.
  • 5Close four known gapsSmall things we already documented as imperfect while building — nothing surprising, all written down.
  • 6Backups and a written handoverHow to restore, how to re-run a file, what to do when something gets stuck.
  • 7Test real Excel filesThe code supports Excel but we've never actually run a real workbook through it.
  • 8Security reviewPasswords are currently in a config file. Needs proper handling before anything goes live.
  • 9Final testing with real data and sign-offRun genuine vendor files end to end and confirm the results are right.

The one thing that could change the timeline: we've only ever tested with tiny files — the biggest was 19 rows. Everything else on the list is predictable work.

If the real files turn out to be moderate in size, we finish about a week early. If they're very large, some of the processing needs reworking and we lose one to two weeks. We'll know within the first two weeks, which is why that test comes first.

Three things I need from you

  1. How big are the real vendor files? Roughly how many rows — thousands, hundreds of thousands, millions? This single number decides whether week 1–2 is easy or hard, and it's the biggest lever on the whole timeline.
  2. Does this run on one server, or does it need to survive a machine failing? It's currently built for a single machine, which matches the original brief. Making it survive hardware failure is a real piece of extra work — worth deciding now rather than in week 7.
  3. Who else will run this besides me? It changes how much handover documentation we need, and right now everything lives with one person.
